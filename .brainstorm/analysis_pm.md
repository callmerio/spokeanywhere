# Role Analysis: Product Manager

## Vision
打造 macOS 平台上最丝滑、最智能的语音与视觉辅助工具。产品不仅要功能强大，更要易于上手，符合 App Store 质量标准。

## Analysis of Questions

1. **里程碑优先级 (发布 vs Alpha)**:
   - **观点**: 即使是 Alpha 版，如果目标是让非开发者朋友使用，App Store (TestFlight) 分发也是最方便的。且沙盒化涉及文件读写权限，越晚做对用户数据的迁移和兼容性挑战越大。
   - **建议**: **优先解决 App Store 合规性**。这是产品走向成熟的必经之路。

2. **核心痛点**:
   - **观点**: 翻译行截断直接影响核心价值（信息获取），是 P0 级 Bug。自定义快捷键是 P1 级需求，影响重度用户的留存。
   - **建议**: **修复 P0 体验问题（翻译截断）**，其次是自定义快捷键。

3. **技术偏好 (本地模型)**:
   - **观点**: 本地模型能作为"隐私安全"和"离线可用"的卖点，但会显著增加安装包体积（可能劝退用户）。目前云端 API 效果好且快。
   - **建议**: **暂缓 P2 本地模型**，除非那是唯一的隐私解决方案。优先优化在线模型的体验（如流式响应、缓存）。

4. **交互体验 (Onboarding)**:
   - **观点**: SpokeAnywhere 需要极其复杂的权限（辅助功能、录音、截图），没有好的引导，用户下载后立刻就会卸载。
   - **建议**: **High Priority**。权限引导流程是产品可用的前提。

## Proposal
1. **P0 - 发布准备**: App Sandbox 适配 + 权限引导流程 (Onboarding)。
2. **P0 - 体验填坑**: 修复翻译截断，优化长文本处理。
3. **P1 - 易用性**: 自定义快捷键，深色/浅色主题适配。
