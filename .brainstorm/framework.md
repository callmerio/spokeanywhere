# Guidance Framework

## Core Challenges Identified

### 1. 视觉反馈悖论 (Visual Feedback Paradox)
- **挑战**: 用户希望“没有明显的框”且“没有变暗”，但必须让用户知道**当前处于截图模式**，且知道**选区在哪里**。
- **风险**: 如果完全透明且无框，用户可能不知道截图已开始，或者不知道自己框选了多大范围。

### 2. 窗口识别的技术路径 (Window Detection Tech Stack)
- **挑战**: 实时识别鼠标下的“窗口”或“UI块”。
- **性能**: 鼠标移动是高频事件 (60Hz+)，实时计算窗口归属可能导致掉帧。
- **准确性**: macOS 窗口层级复杂（重叠、透明窗口、子窗口）。

## Clarifying Questions

### Q1: “无感”的边界在哪里？
- 是完全没有任何遮罩（看到的是原始桌面），还是极低透明度（如 5% 黑色）？
- 选区拖拽时，是否需要虚线或尺寸提示？还是仅保留四个角的控制点？

### Q2: 窗口识别的粒度？
- 仅识别**顶级窗口** (Top-level Windows)？
- 还是需要深入识别**UI 元素** (Buttons, Panels)？（后者需要 Accessibility API，前者可用 ScreenCaptureKit）。

### Q3: 两种模式的共存逻辑？
- 默认进入“窗口识别模式”，拖拽则变为“区域选择模式”？
- 还是需要快捷键切换？
