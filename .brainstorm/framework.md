# Guidance Framework

## Core Challenges Identified

1. **入口问题** - 查词功能放在哪里？Quick Ask？独立面板？设置页？
2. **数据源问题** - 词形变化列表从哪来？本地词形还原还是 API 返回？
3. **UI 复杂度** - 列表视图 + 详情视图的导航状态管理
4. **性能问题** - 实时搜索的防抖、词典 API 延迟处理

## Clarifying Questions

### Q1: 入口与触发方式
- 是否复用现有的 Quick Ask (⌥⌥) 入口？
- 还是独立的快捷键/菜单项？
- 与划词工具栏的"查词"功能如何区分？

### Q2: 词形变化来源
- 是否需要本地词形还原库（如 Lemmatizer）？
- 还是依赖后端 API 返回相关词形？
- Raycast 的词形列表可能来自 macOS Dictionary.app

### Q3: UI 集成方式
- 是否作为 Quick Ask 的一种模式（/define 触发）？
- 还是完全独立的窗口/面板？
- 详情页是否需要滚动查看更多内容？

### Q4: 生词系统集成深度
- 仅高亮显示已有生词？
- 还是支持从查词界面直接管理生词列表？
- 是否与实时字幕的生词高亮联动？
