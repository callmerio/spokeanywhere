# 截图文字标注体验优化设计

> **版本**: v0.1  
> **创建日期**: 2026-04-11  
> **状态**: 已确认，待实现  
> **范围**: 仅覆盖截图编辑器中的文字标注体验优化；不包含“文本贴屏 / 桌面浮动文字”功能

---

## 1. 背景与问题

当前截图选区编辑器已经具备基础标注能力：

- 箭头
- 画笔
- 荧光笔
- 文字
- 橡皮擦

但文字工具的交互仍然停留在“临时输入框 + 轻量对象命中”的混合状态，导致几个用户可见问题同时出现：

1. 正在输入文字时，双击另一处空白区域，光标不会迁移到新位置。
2. 从文字工具切换到其他工具时，原有文字输入光标仍然闪烁。
3. 橡皮擦无法稳定删除已有标注对象。
4. 文字工具没有独立的文字控件扩展，无法直接调整字号与颜色。
5. 已落块的文本缺少明确的“对象态”，无法稳定支持选中、outline、拖动和后续手势调节。

这些问题本质上不是孤立 bug，而是同一个结构性缺陷的外溢：

- 文字草稿态
- 文字选中态
- 文字编辑态
- 当前工具态

上述状态目前没有被显式建模，导致输入框、对象选中、工具切换和命中删除之间互相干扰。

---

## 2. 目标

本次设计的目标是把截图文字标注从“临时输入框行为”升级为“对象化文字标注行为”，并保持与现有截图窗口交互语义一致。

核心目标如下：

1. 修复文字输入与工具切换相关的状态残留问题。
2. 让已落块文字具备稳定的对象态：可选中、可拖动、可再次编辑。
3. 为文字工具增加内联文字控件，支持字号与颜色调整。
4. 为已选中文字块增加手势调节能力：
   - 上下滑调字号
   - 左右滑调透明度
5. 保持橡皮擦为对象级删除，不引入像素级擦除复杂度。
6. 复用现有截图对象模型和窗口交互语义，不做重型架构重写。

---

## 3. 非目标

以下内容明确不在本次设计范围内：

- 桌面浮动文字 / 文本贴屏
- 把剪贴板文本直接生成桌面悬浮对象
- 自由拾色器
- 富文本样式
- 局部橡皮擦 / 像素级擦除
- 文本块旋转、缩放手柄、吸附对齐系统

“文本贴屏 / 桌面浮动文字”应单独形成第二份 spec。

## 4. 方案比较

### 方案 A：继续在现有隐式状态上打补丁

做法：

- 继续在现有 `AnnotationCanvasView` 中补条件分支
- 修复 `finishTextEditing()`、工具切换收口和命中判断

优点：

- 改动最小
- 见效最快

缺点：

- 只能修当前 bug，难以稳定承接新的文字工具栏扩展和手势交互
- 继续放大现有隐式状态问题

### 方案 B：保持现有对象模型，引入显式文字交互状态

做法：

- 继续使用 `AnnotationCanvasView + TextAnnotation + ScreenshotToolbar`
- 但为文字交互引入显式状态模型：
  - `draftText`
  - `selectedText`
  - `editingText`
  - `activeTool`

优点：

- 能同时解决现有 bug 和新增交互需求
- 复用现有标注对象模型
- 实现成本可控

缺点：

- 需要对 `AnnotationCanvasView` 和工具栏状态同步做结构化调整

### 方案 C：将文字层完全拆成独立 overlay 子系统

做法：

- 画笔/荧光笔/箭头保留在 annotation canvas
- 文字标注改成单独文字 overlay 层

优点：

- 长期扩展性最好

缺点：

- 对当前需求明显过重
- 会引入额外的坐标同步和窗口层级复杂度

### 结论

本次采用 **方案 B**。

理由：

- 足以解决现有问题
- 能承接新的文字对象交互
- 不会把当前截图编辑器改造成超出需求的小型设计器

## 5. 设计原则

### 5.1 文字必须是一等对象

文字不能再只是一个临时 `NSTextView` 的残影，而必须具备完整对象生命周期：

- 创建
- 选中
- 编辑
- 拖动
- 删除
- 调整样式

### 5.2 文字输入态与文字对象态分离

输入框是编辑工具，不是最终对象本身。

最终对象是 `TextAnnotation`，输入框只是进入和修改该对象的交互手段。

### 5.3 手势语义复用截图窗口既有规则

当前截图窗口已经存在统一语义：

- 纵向滚动 / 滑动 -> 大小
- 横向滚动 / 滑动 -> 透明度

文字块的手势调节必须复用这套语义，避免学习成本分裂。

### 5.4 橡皮擦保持对象语义

橡皮擦不做局部像素擦除，只做“命中哪个对象，就删除整个对象”的对象级删除。

## 6. 文字交互状态模型

### 6.1 状态定义

本次设计引入以下文字相关状态：

- `activeTool`
  - 当前标注工具
- `draftText`
  - 当前正在输入、尚未落块的文字
- `selectedText`
  - 已落块、被选中的文字对象
- `editingText`
  - 已有文字对象进入再次编辑状态

任一时刻，文字对象只能处于以下三种核心状态之一：

- 无文字交互
- 草稿输入中
- 已选中 / 正在编辑

### 6.2 核心流转

```text
Text Tool Active
  ├─ 双击空白 -> Draft Text
  ├─ 单击文本块 -> Selected Text
  └─ 双击文本块 -> Editing Text

Draft Text
  ├─ 双击另一处空白 -> commit 当前文字 -> 新位置创建新 Draft
  ├─ 切换到其他工具 -> commit 当前文字 -> 退出文字态
  ├─ Enter -> commit
  └─ Esc -> cancel

Selected Text
  ├─ 显示 outline + 外层阴影
  ├─ 可拖动
  ├─ 内联文字控件可直接修改样式
  ├─ 文字工具下手势可调字号/透明度
  └─ 双击 -> Editing Text

Editing Text
  ├─ 复用输入框
  ├─ 完成后回到 Selected Text
  └─ 切换工具时自动 commit
```

## 7. 文字工具行为规则

### 7.1 双击空白

当 `当前工具 = 文字` 时：

- 如果当前没有正在输入的文字：
  - 在双击位置创建新的草稿输入框
- 如果当前已经存在草稿输入框：
  - 先将当前文字 `commit`
  - 再在新位置创建新的草稿输入框

### 7.2 切换到非文字工具

当当前存在未确认文字输入框时：

- 自动确认当前文字
- 结束文字输入框 first responder
- 移除输入框视图
- 清空文字编辑态
- 退出文字对象聚焦态

换言之：

- 离开文字工具时，不允许残留闪烁的文字光标

### 7.3 文本块单击 / 双击

已落块文字对象采用如下规则：

- 单击：
  - 选中该文本块
  - 显示 `outline + 外层阴影`
  - 允许拖动
- 双击：
  - 进入编辑态
  - 显示文字输入框

### 7.4 文字聚焦态的可见范围

只要当前工具不是文字：

- 文本块的 outline 消失
- 文本块的外层阴影消失
- 文本块不再作为“当前被操作对象”保留

也就是说，文字块聚焦态只属于文字工具，不跨工具保留。

## 8. 文字工具栏扩展设计

### 8.1 出现条件

只要 `当前工具 = 文字`，主截图工具栏保持单排横向结构，但会在 `Aa` 按钮右侧直接内联展开文字专属控件。

不采用第二排子工具栏，不采用弹出式面板，也不采用 hover 后再展开。

### 8.2 作用域

内联展开的文字控件同时承担两类作用：

#### 情况 A：当前没有选中文本块

文字控件控制“接下来新建文字”的默认样式：

- 默认字号
- 默认颜色

#### 情况 B：当前选中了某个文本块

文字控件直接映射当前文本块的样式：

- 改字号 -> 当前块立即更新
- 改颜色 -> 当前块立即更新

不需要“应用”按钮。

### 8.3 第一版字段

第一版只包含：

- 字号
- 颜色

透明度不放入工具栏，而是交给手势控制，避免单排工具栏继续膨胀。

### 8.4 UI 形态

推荐使用单排内联形式：

```text
默认
[箭头][画笔][荧光笔][Aa][橡皮擦][撤销][重做][取消][确认][Pin][复制]

文字工具激活后
[箭头][画笔][荧光笔][Aa][A-][16][A+][色板 1][色板 2][色板 3][橡皮擦][撤销]...
```

布局规则如下：

- 工具栏始终保持一条横向栏
- 文字控件只插入在 `Aa` 的右侧
- 其他分组尽量保持原有顺序，不做全栏重排
- 选中 `Aa` 后立即展开，不需要再次点击或 hover

### 8.5 色彩策略

第一版使用固定色板，不做自由拾色器。

原因：

- 截图标注偏快操作
- 色板交互更快
- 复杂度更低

## 9. 文本块手势交互

### 9.1 启用条件

文本块手势调节只在以下条件同时满足时启用：

- `当前工具 = 文字`
- 当前存在已选中的文本块

其他情况下不响应文本块手势，以避免和其他工具行为冲突。

### 9.2 手势语义

复用截图窗口现有交互语义：

- 上下滑 -> 字号变化
- 左右滑 -> 透明度变化

具体行为如下：

- 向上滑：字号变大
- 向下滑：字号变小
- 向右滑：更不透明
- 向左滑：更透明

### 9.3 与现有截图窗口交互的关系

当前截图窗口已经支持：

- 纵向滚动 / 滑动 -> 大小
- 横向滚动 / 滑动 -> 透明度

文字块手势不应该重新发明新的语义，而应直接继承这套规则，只是把作用目标从“整个截图窗口”切换为“当前选中的文本块”。

### 9.4 视觉反馈

第一版采用轻量反馈：

- 文本块选中时显示 `outline + 外层阴影`
- 手势变化实时反映在文本块本身
- 不额外引入复杂 HUD

如果未来需要，可再补充轻量数值浮层，但不作为当前设计必需项。

## 10. 橡皮擦与命中规则

### 10.1 橡皮擦语义

本次明确采用 **对象级橡皮擦**：

- 擦到哪个对象，就删除整个对象
- 不支持局部擦除

适用对象包括：

- 文本块
- 箭头
- 整段画笔笔迹
- 整段荧光笔笔迹

### 10.2 命中规则

#### 文本块

- 命中区域 = 文本 bounding rect + 适度 padding

#### 箭头

- 命中区域 = 箭头整体 expanded bounds

#### 画笔 / 荧光笔

需要从当前的轻量点集命中判断升级为更稳定的 stroke 线段距离判断。

目标是：

- 删除笔迹中段时也能稳定命中
- 不依赖用户一定擦到采样点附近

### 10.3 橡皮擦 hover 反馈

在橡皮擦模式下：

- hover 到可删除对象时提供明显反馈
- 点击即删

反馈优先级高于普通 hover 光标切换，避免 `openHand` 和 `eraserCursor` 互相打架。

## 11. 状态收口规则

当前所有能够改变文字交互状态的入口，都必须先经过统一收口流程：

```text
工具切换 / 双击空白 / 双击文本块 / 橡皮擦点击
        │
        ▼
先收口当前文字态
(commit 或 cancel)
        │
        ▼
清理 firstResponder / 输入框 / 旧聚焦
        │
        ▼
进入新状态
(draft / selected / editing / erasing)
```

这意味着：

- 不能再允许文字输入框作为孤立子视图长期悬挂
- 不能再让工具切换只更新 cursor、不收口文字状态

## 15. 风险与控制

### 风险 1：`AnnotationCanvasView` 状态继续膨胀

缓解：

- 不新增零散条件分支
- 先收口文字状态，再补工具栏和手势

### 风险 2：文本块手势与其他工具滚轮行为冲突

缓解：

- 明确限制为 `文字工具 + 已选中文本块` 才启用

### 风险 3：橡皮擦命中修复后影响拖动命中

缓解：

- 将“普通对象 hover / 选中命中”和“橡皮擦命中”分别验证
