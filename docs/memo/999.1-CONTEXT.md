# Phase 999.1: 桌面文本贴屏 Overlay - Context

**Gathered:** 2026-04-13
**Status:** Ready for planning

<domain>
## Phase Boundary

本 phase 交付“桌面文本贴屏 Overlay”能力：将文本内容以桌面悬浮对象的形式展示，支持预览态、双击进入编辑、拖动、缩放、透明度调整与 Pin 语义。

这项能力与截图文字标注 phase 明确分离，不混入截图编辑器内部的文字 annotation 体系。

第一版的产品边界：
- 支持将剪贴板文本创建为桌面文本对象
- 对象默认以主题化预览态显示，而不是一直暴露文本输入框
- 支持轻量 Markdown 展示
- 支持与截图 Pin 窗口尽量一致的桌面交互体验

明确不在本 phase 第一版范围内：
- 完整富文本 / 笔记系统
- 样式设置页、字体/背景/主题自定义
- 真正挂到 Finder 桌面层的系统级“桌面便签”
- 把该需求并入截图文字标注 phase

</domain>

<decisions>
## Implementation Decisions

### 对象模型
- **D-01:** 桌面文本贴屏对象必须是**活的文本对象**，不是先光栅化成透明图片再贴屏。
- **D-02:** 用户感知上它应当像“已经排版好的贴纸/页面预览”，而不是一个始终闪光标的输入框。
- **D-03:** 第一版样式固定为单一主题风格，方向参考用户提到的 `Groovebox` 气质；暂不开放背景色、字体、主题切换。

### 交互语义
- **D-04:** 默认状态是**预览态**，不是编辑态。
- **D-05:** **双击**是进入编辑的唯一核心语义；双击后进入文本编辑。
- **D-06:** 编辑态不应退化成“生硬的普通文本框”，应尽量保持与预览态一致的主题感。
- **D-07:** 长文本场景可以向 Apple 便利贴 / Raycast Notes 的 pinned note 体验靠拢，但仍以“桌面预览对象”而非完整笔记产品为目标。

### Markdown 范围
- **D-08:** 第一版采用**轻量 Markdown 子集**，用于把文本渲染得更规整，而不是上完整 Markdown 编辑器。
- **D-09:** 第一版至少支持：
  - `# / ##` 标题
  - 普通段落
  - 换行
  - `-` 列表
  - `**粗体**`
- **D-10:** 第一版不做：
  - 表格
  - 图片
  - 任务列表
  - 引用块
  - 链接卡片
  - 复杂代码块 / 高亮
  - 用户自定义颜色

### 入口与生命周期
- **D-11:** 最终要支持多个入口，但**第一入口优先做剪贴板文本**。
- **D-12:** 语音转录文本入口是明确需要的后续入口，应复用同一对象模型，而不是做成另一套系统。
- **D-13:** 对象创建后默认即为 **pinned**，不是“临时悬浮后再点 pin”。
- **D-14:** Pin 语义与现有截图窗口保持一致：属于桌面上的可交互悬浮对象，而不是 Finder 桌面层 hack。

### 与截图体系的一致性
- **D-15:** 桌面文本对象应尽量复用截图 pin 窗口的交互手感，包括拖动、缩放、透明度、工具栏语义。
- **D-16:** 虽然默认即 pinned，但仍应保留与截图窗口一致的工具栏/图钉语义，以便后续做 unpin / lock / close 等统一操作。

### the agent's Discretion
- 具体的文本数据模型命名与持久化结构
- 轻量 Markdown 解析方式与渲染实现细节
- 预览态与编辑态之间的过渡动画
- 工具栏露出方式与 hover 细节
- 主题细节中的留白、圆角、阴影、字阶

</decisions>

<specifics>
## Specific Ideas

- 用户明确希望它“看起来像一个已经生成好的页面/图片预览”，而不是一个普通输入框。
- 用户明确要求：双击之后唯一重要语义就是“编辑文本”。
- 用户希望它支持“非常简易的 Markdown”，核心目的是获得更规整的标题/段落结构。
- 第一版风格先固定，后续再通过右键或设置页进入样式配置。
- 长文本体验可参考：
  - Apple 原生便利贴
  - Raycast Notes 的 pinned note
- Pin 语义希望贴近现有截图窗口：对象创建后就是一个桌面悬浮交互对象，且与右下角图钉按钮的产品认知保持一致。

</specifics>

<code_context>
## Existing Code Insights

### Reusable Assets
- `spoke/UI/Screenshot/ScreenshotWindow.swift`：现成的 borderless / floating / nonactivating 截图窗口，已具备拖动、滚轮/触控板缩放、透明度、Pin/Lock 语义
- `spoke/Core/Screenshot/ScreenshotManager.swift`：现成的窗口生命周期、持久化、恢复、Pin/Unpin 逻辑
- `spoke/Core/Screenshot/ScreenshotItem.swift`：现成的可观察对象字段范式，可为文本对象数据模型提供参考
- `spoke/UI/HUD/FloatingPanel.swift`：已有其他悬浮窗口模式，可提供窗口层级与行为参考

### Established Patterns
- 当前项目已经有稳定的 AppKit 悬浮窗口模式：`NSPanel` / `NSWindow` + `.floating` + `collectionBehavior`
- 截图窗口已经建立了“桌面悬浮对象”的成熟交互语义，是本 phase 最重要的复用对象
- 仓库当前采用 repo-native GSD 记录方式：`ROADMAP.md + plan/ + issues/ + docs/*`，而不是 `.planning/`

### Integration Points
- 剪贴板入口可以参考现有 `ClipboardPipelineService` 一类的文本来源能力
- 语音入口后续可从现有转录/记录链路接入，但第一版不应为此改写对象模型
- 工具栏和 hover 交互应优先参考 screenshot window 现有动作条模型，而不是另起一套完全不同的桌面控件

</code_context>
