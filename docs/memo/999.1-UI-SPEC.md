# Phase 999.1 - UI Design Contract

> Visual and interaction contract for the native macOS `桌面文本贴屏 Overlay`.
> This document exists to stop drift in hover, glow, cursor, resize, drag, and edit semantics.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Platform | Native macOS `NSPanel` / AppKit floating overlay |
| Style source | `DesignTokens` only |
| Interaction reference | `ScreenshotWindow` + `ScreenshotContentView` |
| Overlay metaphor | A pinned reading card / page preview, not a debug panel and not a plain text field |
| Theme count | 1 fixed theme in v1 |
| Out of scope | Theme picker, rich text editor, Finder desktop-layer hacks, screenshot annotation merge |

### Native Contract Summary

- The overlay must feel like a finished desk object that happens to become editable, not like an editor that happens to float.
- Preview and edit are two states of the same card. They may change responder behavior, but they must not change the visual world.
- Hover, mark, and resize feedback must reuse screenshot state color rules before adding any phase-specific ornament.

### Registry Safety

- This phase is native macOS AppKit/SwiftUI overlay UI with `DesignTokens` as the only styling source.
- No shadcn preset, no component registry, no third-party design blocks, and no imported registry code are allowed in this contract.
- Any missing primitive must be added repo-native through `DesignTokens` or native overlay code.

## Visual System

### Object Identity

- The object is a quiet, warm-on-dark pinned reading card.
- Default impression: "composed page pinned on desktop", not "development tool panel", "inspector", or "floating form field".
- Chrome stays secondary. Text remains the visual subject.

### Base Card Rules

| Element | Contract |
|---------|----------|
| Card fill | `DesignTokens.Colors.NS.pinnedTextBackground` (`#222222`) |
| Text color | `DesignTokens.Colors.NS.pinnedTextForeground` (`#DCCEA9`) |
| Corner radius | `DesignTokens.CornerRadius.xl` (`16pt`) |
| Base border | `1pt`, same warm foreground hue at `16%` alpha |
| Ambient shadow | Neutral black shadow only; no colored idle glow for pinned idle state |
| Glow layer | Outside the card perimeter only; never tint the content fill |
| Toolbar layer | Accessory layer above the card, never the focal layer |

### Visual Non-Goals

- No neon edge strips.
- No gradient halos unrelated to screenshot glow semantics.
- No always-visible resize handles in idle state.
- No white `NSTextView` background, inset field bezel, or default AppKit form chrome.
- No extra "selected" border color independent from the existing state priority.

## Spacing And Chrome Rules

### Window And Card Geometry

| Token / Value | Contract |
|---------------|----------|
| Default content width | `320pt` at zoom `1.0` |
| Min content width | `280pt` |
| Max content width | `760pt` |
| Min window height | `160pt` |
| Max window height | `540pt`; overflow scrolls inside the card |
| Glow safety padding | `16pt` minimum between card edge and window edge; if missing in tokens, add a token before implementation |
| Content side inset | `16pt` left / right |
| Content bottom inset | `16pt` |
| Top chrome rail | `24pt` reserved inside the card for utility chrome |
| Content start below rail | additional `8pt` gap below the chrome rail before first text line |
| Action bar inset | `8pt` from top and trailing card edges |

### Chrome Layout Rules

- The action bar lives inside the top-right chrome rail, not on top of the first paragraph.
- The first visible text baseline must never be overlapped by buttons at default width.
- The preview scroll view and editor scroll view must share the same content box.
- Any glow padding, resize band padding, or hover affordance padding must be accounted for in window sizing so nothing clips.

### Density Rules

- Preview density should be page-like, not note-app panel-like.
- Space comes from typography rhythm first, not from oversized container padding.
- Vertical space is earned by paragraph rhythm, heading spacing, and list indent, not by blank dead margins around all content.

## Typography Rules

### Allowed Type Ramp

| Role | Size | Weight | Line Height / Rhythm |
|------|------|--------|----------------------|
| Utility / button tooltip baseline | `caption token` | regular | `1.25`; one short line only |
| Body paragraph | `16pt` | regular | approx `1.5` with `4pt` line spacing and `8pt` paragraph spacing |
| `##` heading | `20pt` | semibold | approx `1.25` with `8pt` spacing after |
| `#` heading | `22pt` | semibold | approx `1.2` with `8pt` spacing after |

### Markdown Rendering Rules

- Paragraphs use the body style.
- `**bold**` uses semibold, not a separate color.
- List bullets align to a `16pt` hanging indent.
- Text remains left-aligned and wraps by word.
- Empty lines create rhythm, but they do not create giant card padding.

### Preview/Edit Continuity

- Preview and edit use the same base body size and the same foreground color.
- Edit mode may expose selection and insertion caret behavior, but it must not switch to a different background, different type scale, or different mood.
- The insertion point uses the same warm foreground family as the text, not system accent blue.

## Color And State-Color Rules

### Base Palette

| Role | Value | Usage |
|------|-------|-------|
| Base surface | `#222222` | Card fill, edit background, preview background |
| Primary ink | `#DCCEA9` | All content text, inline emphasis, insertion point, subtle border family |
| Hover accent | `DesignTokens.Colors.NS.glowHoverStroke` + `glowHoverShadow` | Hover glow, resize affordance, active spatial manipulation |
| Mark accent | `DesignTokens.Colors.NS.glowMarkStroke` + `glowMarkShadow` | Persistent marked state only |
| Future unpinned accent | `DesignTokens.Colors.NS.glowIdle` | Only when object is unpinned; not used for normal pinned idle |
| Destructive | `DesignTokens.Colors.NS.error` | Close affordance only |
| Informational utility | `DesignTokens.Colors.NS.accentInfo` | Lock button active state only |

### State Priority

The overlay must use exactly this visual priority order:

1. `Marked`
2. `Hover / active spatial manipulation`
3. `Unpinned idle`
4. `Pinned idle`

### Color Proportion Note

- Keep the visible balance near `60 / 30 / 10`: base surface remains dominant, primary ink and secondary chrome remain supportive, and accent colors stay confined to state feedback.
- Hover blue and mark orange may appear on outer glow, resize marks, and active icon states only. They must never overtake the card fill or become the dominant read of the object.

### State Color Usage Rules

- Mark changes the outer state treatment only. It does not recolor the text body or card fill.
- Hover blue is temporary and spatial. It communicates "this object is currently interactable".
- Orange is persistent and semantic. It communicates "this object is marked".
- Red is reserved for destructive close affordances and must not appear as a generic hover color.
- Blue or orange must not be used as decoration inside the markdown content.

## Interaction Contract

### Core Modes

| Mode | Entry | Visible Contract | Allowed Actions |
|------|-------|------------------|-----------------|
| Preview idle | Pointer outside card | No hover glow, no resize marks, toolbar hidden | Double-click to edit, hover to reveal affordances |
| Preview hover | Pointer inside body but outside resize band | Blue hover glow, toolbar fade-in, content remains visually dominant | Drag, double-click edit, toolbar actions |
| Resize hover | Pointer enters resize band | Same state glow plus visible resize marks on relevant edge/corner | Edge or corner resize |
| Dragging | Mouse drag begins in body, not on toolbar, not in resize band, unlocked only | Card moves, blue active state persists, cursor closes to drag state | Move object |
| Resizing | Mouse drag begins in resize band, unlocked only | Active edge/corner marks stay visible during resize | Resize object |
| Editing | Double-click from preview | Same card and typography world, action bar remains available, no field chrome | Edit text, select text, commit or cancel |
| Locked spatial state | Lock toggled on | Hover may still show focus, but no drag/resize marks appear | Read, edit, mark, unpin, close |

### Hover Contract

- Hover begins when the pointer enters the interactive card bounds.
- Hover must show the screenshot-style blue glow within `80ms`.
- Hover must reveal the action bar with a short fade (`150ms` to `200ms`).
- Hover must not introduce a second border treatment unrelated to the screenshot glow recipe.
- Hover alone does not imply resize. Resize requires a separate visible affordance described below.

### Glow Contract

- Use the same stroke-and-shadow model as screenshot windows.
- For pinned text overlays, idle pinned state has no colored glow.
- Hover uses the screenshot blue glow recipe.
- Mark uses the screenshot orange glow recipe.
- Unpinned idle may use the screenshot cream glow recipe in the future, but only when `isPinned == false`.
- Glow priority never changes by subview. The whole object speaks with one outer-state language.

### Mark Contract

- Mark is persistent until the user unmarks.
- Mark is visible even when the pointer leaves the object.
- Mark does not change typography, padding, toolbar layout, or resize geometry.
- When marked and hovered, the outer state remains orange. Hover does not override mark.

### Resize Contract

#### Hit Geometry

- The resize interaction band is an `8pt` ring measured from the card edge.
- Corner zones take precedence over edge zones.
- Corner zones occupy at least a `16pt x 16pt` square from each corner inward.
- Resize never starts from inside the main text body unless the pointer is inside that resize band.

#### Visible Resize Affordance

- Entering the resize band must show a visible resize marker in addition to any cursor change.
- The required marker is:
  - a `2pt` inset edge rail on the active edge, or
  - an `L`-shaped corner mark on the active corner, using the current state accent color.
- The marker appears within `80ms` of entering the resize band.
- The marker persists for the full active resize gesture, even if the cursor itself is not captured in screenshots or recordings.
- The marker disappears when the pointer returns to the body interior or when the object becomes locked.

#### Resize Behavior

- Edge resize changes a single axis.
- Corner resize changes both axes.
- Resizing reflows the markdown preview live.
- Resizing clamps to the declared minimum and maximum size rules.
- Resizing must not enter edit mode.

### Drag Contract

- Unlocked preview body uses a drag affordance distinct from resize.
- Drag starts only from the preview body, not from toolbar buttons and not from the resize band.
- Active drag uses the same temporary hover-blue state language.
- Drag never recolors the card fill or text.
- Lock disables drag, but does not disable double-click editing.

### Edit Contract

- Double-click is the only required entry into editing in v1.
- Single click in preview never enters editing.
- While editing:
  - the card stays visually the same card,
  - the action bar remains accessible,
  - resize affordance is suppressed,
  - content drag is suppressed,
  - text selection and caret behavior are allowed.
- Commit paths:
  - focus loss commits,
  - `Cmd+Enter` commits,
  - `Escape` cancels to the previous snapshot.

### Scroll And Gesture Contract

- Vertical scroll inside the text overlay scrolls content, not object size.
- If opacity adjustment is retained, it must follow the existing screenshot modifier pattern and must not conflict with ordinary reading scroll.
- Do not overload ordinary vertical content scrolling to resize the text overlay.

## Cursor Contract

### Principle

Cursor is confirmatory, never primary.

The implementation fails this contract if cursor changes are the only signal for resize or drag semantics.

### Cursor Map

| Region / Mode | Cursor |
|---------------|--------|
| Preview body, unlocked | `openHand` |
| Active drag | `closedHand` |
| Preview body, locked | `arrow` |
| Editing text body | `IBeam` |
| Toolbar buttons | `pointingHand` |
| Left or right resize band | horizontal resize cursor |
| Top or bottom resize band | vertical resize cursor |
| Corner resize band | corner-appropriate resize cursor when AppKit provides one; otherwise nearest system resize cursor plus visible corner mark |

### Cursor Guardrails

- `openHand` is allowed only for draggable body hover, never for resize regions.
- `closedHand` is allowed only during active drag, never as the steady-state resize cursor.
- If AppKit lacks a native diagonal cursor for a corner, use the closest system resize cursor. A custom diagonal cursor is optional polish, not a release requirement.
- Locked state must not advertise drag or resize with cursor.
- Because screenshots often omit the cursor, the overlay must always pair cursor changes with visible state change: hover glow for drag, mandatory edge rail for edge resize, and mandatory corner mark for corner resize.

## Action Bar Contract

### Layout And Presence

- The action bar is an accessory strip, not an always-on command center.
- It sits in the top-right chrome rail.
- It fades in on hover and stays visible during editing.
- It hides when the object returns to preview idle.

### Button Semantics

| Control | State Color | Meaning |
|---------|-------------|---------|
| Lock | info blue when active | Freeze spatial movement and resize only |
| Mark | orange when active | Persistent semantic mark |
| Pin | orange when active | Space-pinning state |
| Close | red on hover / press only | Destructive close |

### Prohibitions

- Do not let the action bar overlap the first readable text line.
- Do not increase button count in v1.
- Do not use the action bar as the primary communication layer for resize or drag semantics.

## Copywriting Contract

### Empty And Failure States

| Surface | Required Copy | Contract |
|---------|---------------|----------|
| Blank / empty overlay | `No text to display yet.` | Show only when the overlay object exists but the resolved text payload is empty or whitespace-only. |
| Empty overlay helper | `Paste or type text, then double-click to edit.` | Secondary helper line for the empty state only. Hide it as soon as content exists. |
| Render / load failure | `Couldn't render this text overlay.` | Use for markdown render failure or source-load failure. Never expose parser jargon, file paths, or stack traces. |
| Recovery primary action | `Try Again` | Retries the render or load path in place. |
| Recovery secondary action | `Edit Text` | Opens raw text editing on the current snapshot so recovery never dead-ends. |

### Action Bar Tooltip And Accessibility Labels

| Control | Tooltip | Accessibility Label |
|---------|---------|---------------------|
| Lock inactive | `Lock position and size` | `Lock overlay position and size` |
| Lock active | `Unlock position and size` | `Unlock overlay position and size` |
| Mark inactive | `Mark overlay` | `Mark text overlay` |
| Mark active | `Unmark overlay` | `Unmark text overlay` |
| Pin active | `Unpin from desktop` | `Unpin text overlay from desktop` |
| Pin inactive | `Pin to desktop` | `Pin text overlay to desktop` |
| Close | `Close overlay` | `Close text overlay` |

### Destructive Close Semantics

- Close removes the overlay from the desktop immediately and does not show a blocking confirmation sheet in v1.
- If close is triggered while editing, the current text buffer is committed first so the latest typed content is not dropped.
- This phase does not require a separate close-confirm modal or a dedicated undo flow. If a restore action is added later, its label should be `Reopen Last Closed Overlay`.
- Close remains visually destructive only on hover or press; it must not read as a permanent warning in idle state.

## Do / Don't

### Do

- Reuse screenshot glow color priority exactly.
- Use visible resize rails or corner marks whenever the pointer enters the resize band.
- Use `openHand` / `closedHand` only for drag semantics.
- Keep preview and edit in the same visual theme.
- Reserve a quiet chrome rail so utility controls do not sit on top of the content.
- Let typography rhythm create the "page" feeling.

### Don't

- Do not use cursor as the only resize hint.
- Do not map resize hover to `openHand`.
- Do not invent a second glow language just for text overlay.
- Do not place the action bar directly over paragraph text.
- Do not recolor the whole card blue or orange for hover / mark.
- Do not make edit mode fall back to a standard white AppKit text field look.
- Do not use scroll-to-resize for ordinary reading content.

## Acceptance Criteria

All criteria below must be observable live without needing a screenshot of the cursor.

### Visual Acceptance

- [ ] A newly created overlay appears as a warm dark reading card, not as a white or system-default text field.
- [ ] In pinned idle state, the card has no colored outer glow.
- [ ] The first readable text line is never covered by the action bar at default width.
- [ ] Preview and edit share the same background, type family, and overall mood.

### Hover And State Acceptance

- [ ] Hovering the card body shows the screenshot-style blue glow within `80ms`.
- [ ] Marked state remains visibly orange after hover exits.
- [ ] Hover does not override marked orange on the outer state treatment.
- [ ] Lock does not change the theme; it only changes allowed interactions.

### Resize Acceptance

- [ ] Moving into the resize band reveals a visible edge rail or corner mark within `80ms`.
- [ ] The visible resize marker is present even if the cursor is not visible in a screenshot or screen recording.
- [ ] Dragging from the resize band changes the frame along the expected axis or corner pair.
- [ ] Dragging from the body interior moves the card instead of resizing it.
- [ ] Lock removes resize markers and prevents resize from starting.

### Edit Acceptance

- [ ] Single click in preview does not enter editing.
- [ ] Double-click in preview enters editing.
- [ ] While editing, text selection works and the body surface does not revert to system field chrome.
- [ ] While editing, resize affordance is hidden and spatial drag does not start from the text body.
- [ ] `Cmd+Enter` commits, `Escape` cancels, and focus loss commits.

### Copywriting Acceptance

- [ ] Empty overlays use `No text to display yet.` with the helper line `Paste or type text, then double-click to edit.` only while content is absent.
- [ ] Render or load failure uses `Couldn't render this text overlay.` with `Try Again` and `Edit Text` as the recovery actions.
- [ ] Every icon-only action bar item exposes the specified tooltip and accessibility label.
- [ ] Close does not open a confirmation sheet and commits the current text buffer before the overlay disappears.

### Drift-Prevention Acceptance

- [ ] Reviewers can tell the difference between hover, resize-hover, drag, resize, marked, and locked states by looking at the object itself, without relying on cursor capture.
- [ ] No implementation introduces a new border, glow, or toolbar behavior that conflicts with the screenshot reference contract.
- [ ] No resize region falls back to `openHand`.
