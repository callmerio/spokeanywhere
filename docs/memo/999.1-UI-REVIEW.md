## Findings

### 1. P0 — 预览态的信息密度和空间分配仍然不像“贴文”，而像一个被放大的调试面板

**Evidence**
- 用户提供的截图中，预览态内容仍显得“像一块大容器里塞了调试文字”，缺少真正的贴文/页面感。
- [PinnedTextMarkdownRenderer.swift](/Volumes/1TBSSD/offload/Workspace/macos/spokeanywhere/spoke/UI/DesktopText/PinnedTextMarkdownRenderer.swift#L12)
  仍然使用固定 `contentInsets`，并通过统一 bounding rect 估算窗口高度。
- [PinnedTextContentView.swift](/Volumes/1TBSSD/offload/Workspace/macos/spokeanywhere/spoke/UI/DesktopText/PinnedTextContentView.swift#L130)
  内容区仍按单一 inset 盒模型裁切，页面结构没有额外的密度层级。

**Why this matters**
- 这会直接让用户把它感知成“开发态文本容器”，而不是“桌面贴文”。
- 只改颜色无法解决这个问题，必须继续收口内容密度和排版节奏。

### 2. P0 — 当前 hover / glow 语义在设计方向上反复摇摆，说明交互契约还没有稳定

**Evidence**
- [PinnedTextContentView.swift](/Volumes/1TBSSD/offload/Workspace/macos/spokeanywhere/spoke/UI/DesktopText/PinnedTextContentView.swift#L299)
  现在是 screenshot-style 的通用 glow；此前又被改成边框亮带，说明我们还在试错而非稳定收敛。
- [PinnedTextWindow.swift](/Volumes/1TBSSD/offload/Workspace/macos/spokeanywhere/spoke/UI/DesktopText/PinnedTextWindow.swift#L263)
  hover 状态由 window 层分发，但 cursor 语义和 glow 语义还在人工拼接阶段。

**Why this matters**
- 视觉与交互如果没有统一契约，会导致每轮看起来都“能动了”，但整体越来越散。
- 用户已经明确表达要和 screenshot 统一，这里不该再引入新的局部语言。

### 3. P1 — 工具条在预览内容上的存在感偏强，仍然有“盖在贴文上”的开发控件感

**Evidence**
- [PinnedTextActionBarView.swift](/Volumes/1TBSSD/offload/Workspace/macos/spokeanywhere/spoke/UI/DesktopText/PinnedTextActionBarView.swift#L28)
  目前 action bar 直接放了 `lock / mark / pin / close` 四个按钮。
- [PinnedTextContentView.swift](/Volumes/1TBSSD/offload/Workspace/macos/spokeanywhere/spoke/UI/DesktopText/PinnedTextContentView.swift#L141)
  action bar 仍然直接贴在右上角内容区域上方，没有更细的显隐或弱化策略。

**Why this matters**
- 对贴文型对象来说，工具条应该是“辅助层”，而不是第一眼的视觉中心。
- 当前按钮组容易抢走内容本身的注意力。

### 4. P1 — 当前 resize cursor 只是“技术上可用”，但还没有形成一等交互提示

**Evidence**
- [PinnedTextWindow.swift](/Volumes/1TBSSD/offload/Workspace/macos/spokeanywhere/spoke/UI/DesktopText/PinnedTextWindow.swift#L335)
  目前只是根据 `ResizeRegion` 切换系统 cursor。
- [PinnedTextWindow.swift](/Volumes/1TBSSD/offload/Workspace/macos/spokeanywhere/spoke/UI/DesktopText/PinnedTextWindow.swift#L289)
  resize hit 区仍是很薄的一圈几何判断，没有更明显的 hover affordance。

**Why this matters**
- 这解释了为什么用户会持续要求“边角 hover 的反馈”，因为单靠 cursor 还不够。
- 但这类 affordance 必须服从 screenshot 的统一语言，不能再做成另一套特效系统。

### 5. P1 — 预览态和编辑态虽然比最早更接近，但还没有达到“同一个产品”的视觉连续性

**Evidence**
- [PinnedTextContentView.swift](/Volumes/1TBSSD/offload/Workspace/macos/spokeanywhere/spoke/UI/DesktopText/PinnedTextContentView.swift#L167)
  双击进入编辑后，编辑文本是同主题色，但仍然是标准 `NSTextView` 语义。
- [PinnedTextContentView.swift](/Volumes/1TBSSD/offload/Workspace/macos/spokeanywhere/spoke/UI/DesktopText/PinnedTextContentView.swift#L337)
  预览态只是简单给 `previewTextView` 设置字体与颜色，缺少更强的视觉语义桥接。

**Why this matters**
- 当前已经从“完全割裂”改善到“勉强同主题”，但还没有达到用户期望的“预览就像一个页面，编辑也保持那个世界观”。

## Top Fixes

1. 先冻结交互契约：`hover = screenshot 蓝色通用 glow`、`mark = 橙色`、`resize = 系统 cursor + 轻量 affordance`，不再做独立特效路线。
2. 收紧内容密度：继续削减无效 padding，并针对标题、段落、列表做更明确的版式层级，而不是只靠统一行距。
3. 弱化 action bar：降低默认存在感，让内容继续成为视觉主体。
