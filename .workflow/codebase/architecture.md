# Architecture

## Overview

SpokenAnyWhere is a single Swift Package executable with a service-oriented native macOS architecture. The main app target compiles four source layers: `App/`, `Services/`, `Core/`, and `UI/`.

## Layers

| Layer | Responsibility | Examples |
|-------|----------------|----------|
| `App/` | SwiftUI/AppKit entry point, lifecycle orchestration, menu/status wiring, runtime adapters | `SpokenlyApp`, `AppDelegate`, `AppLifecyclePlan` |
| `Services/` | Global singleton services/managers, dependency injection facade, event orchestration | `ServiceContainer`, `RecordingController`, `QuickAskService`, `HotKeyService` |
| `Core/` | Feature-domain business logic and data models | Audio, Transcription, LLM, Workflow, LiveCaption, Screenshot, Dictionary, SwiftData models |
| `UI/` | SwiftUI views and AppKit panels/windows | Settings, HUD, LiveCaption, Screenshot, MessagePanel, SelectionToolbar |

## Entry and Runtime Flow

- `SpokenAnyWhereApp` is the SwiftUI `@main` entry and adapts `AppDelegate`.
- `AppDelegate` owns launch/shutdown orchestration, status menu, settings window, runtime adapters, and app-level service wiring.
- `AppLifecyclePlan` defines ordered startup/shutdown steps.
- `AppDelegateLiveDependencies` bridges AppDelegate to `ServiceContainer` live services.

## Dependency Pattern

- `ServiceContainer` is a `@MainActor` singleton DI facade.
- Services are lazy-resolved from `ServiceContainerDependencies` factory closures.
- Major services expose protocols and `register(...)` methods for test injection.
- SwiftUI receives services through `\.services` environment.

## Data Flow Highlights

- Hotkeys flow through `HotKeyService` callbacks into feature controllers.
- Recording flows through `RecordingController` → audio/transcription → optional LLM processing → history/message panel/clipboard/HUD.
- Quick Ask collects voice/manual input plus OCR, clipboard, live caption, and attachment context before calling `LLMPipeline`.
- Live captions coordinate audio capture, transcription, translation, caption segment persistence, and caption window UI.
- Screenshot and pinned text use AppKit runtime adapters and manager-owned window factories.

## Architectural Rules

- Keep domain logic in `Core/`, orchestration in `Services/`, UI/window code in `UI/`, and startup wiring in `App/`.
- Add new services through dependency structs, live dependency factories, and `ServiceContainer` accessors.
- Preserve separation of shared resources such as audio callback sessions, hotkeys, pasteboard, and windows.
- Avoid expanding `AppDelegate` with feature internals; prefer lifecycle step IDs and runtime adapters.
