# Cross-Cutting Concerns

## Overview

SpokenAnyWhere has mature native macOS infrastructure for structured logging, SwiftData persistence, Keychain-backed secrets, TCC permissions, Swift concurrency bridging, and broad test coverage. Current risk areas include privacy-sensitive logging, fatal persistence initialization, uneven screen-capture permission strategy, and concurrency escape hatches.

## Concerns

| Concern | Current Pattern | Notes |
|---------|-----------------|-------|
| Error handling | Domain errors and graceful nil returns in many services; fatal SwiftData startup failure in `AppDelegate` | Consider recovery UX for store corruption/migration failures |
| Logging | `Logger(subsystem: "com.spokeanywhere", category: ...)` | Avoid public logging of user text, endpoint details, or auth fragments |
| TCC permissions | Bundler usage strings plus helper/service wrappers | Screen capture permission checks vary by feature |
| Configuration | `@AppStorage`, UserDefaults, SwiftData profile config | `AppSettings` and `LLMSettings` are main config surfaces |
| Persistence | SwiftData metadata plus file-system artifacts for audio/screenshots/captions | History cleanup and storage stats exist |
| Secrets | API keys stored in Keychain; SwiftData stores references | Debug simple-storage path must remain disabled in release |
| Concurrency | MainActor service model with runtime bridge helpers | Audit `@unchecked Sendable`, `@preconcurrency`, `nonisolated(unsafe)`, and transfer boxes |
| Testing | Swift Testing unit tests and XCTest UI tests | Some shared-state tests are serialized |

## Privacy and Security Notes

- Treat transcriptions, prompts, LLM responses, request URLs, and auth header fragments as private.
- Keep remote AI consent and local-first constraints visible in workflow planning.
- Validate that crash logs and diagnostics do not persist sensitive user content.

## Quality Notes

- Use `swift build`, `swift test --parallel`, and `./Tests/run-concurrency-check.sh` for local quality gates.
- Sanitizer verification is CI-only when local macOS policy blocks sanitizer loading.
- Keep concurrency escape hatches small, documented by necessity, and test-covered where possible.
