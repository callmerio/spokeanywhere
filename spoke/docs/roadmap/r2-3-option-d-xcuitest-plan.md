# R2-3 Option D 计划（XCTest UI 正式化）

版本：v1  
日期：2026-02-23  
状态：规划中（不在 M2 立即实施）

## 1. 目标

在不影响 M2 收敛的前提下，于 R3/R4 建立可持续的 macOS UI 自动化基线：

1. 为 SpokenAnyWhere 补齐 Xcode 工程与 UI Test target。
2. 将录音/截图/字幕三条关键链路纳入可重复执行的 UI 自动化。
3. 形成 CI 可执行的稳定门禁（失败阻断）。

## 2. 范围边界

### In Scope

- Xcode 工程化（`.xcodeproj`/scheme/UI test bundle）。
- 最小 UI 自动化基线（3 条关键链路）。
- CI 执行入口与失败回传。

### Out of Scope

- 新产品功能开发。
- 大规模 UI 重构。
- 与稳定性无关的测试平台扩展。

## 3. 分期路线

## R3：基础设施与最小链路（建议 2 周）

### D1 工程与 Target 建设

- 创建 `SpokenAnyWhere.xcodeproj`（或等效工程化方案）。
- 新建 UI Test target（例如 `SpokenAnyWhereUITests`）。
- 定义共享 scheme（本地 + CI 一致）。

验收门槛：

- `xcodebuild -list` 可见 app + UI tests。
- UI tests target 可编译通过（即使测试用例为空）。

### D2 可测性最小改造

- 仅增加测试可观测/可定位元素（identifier、启动参数、测试环境标记）。
- Debug-only 测试钩子隔离，不进入 Release 路径。

验收门槛：

- Release 构建不包含测试钩子。
- 核心页面元素可被 UI tests 稳定定位。

### D3 首批 E2E 用例

- 用例 1：录音链路（开始/停止/结果可观测）。
- 用例 2：字幕链路（开/关状态变化可观测）。
- 用例 3：截图链路（触发后有完成日志或产物）。

验收门槛：

- 本地连续 10 次通过率 >= 90%。
- 单轮执行时长 <= 5 分钟。

## R4：CI 门禁与治理（建议 1-2 周）

### D4 CI 集成与并行策略

- 在 CI 增加 UI 自动化 job（独立于单元测试）。
- 输出结构化工件（日志、截图、失败上下文）。

验收门槛：

- PR 可见 UI 自动化结果。
- 失败时能定位到具体步骤与日志窗口。

### D5 阈值固化与解冻评审

- 固化通过阈值（成功率、时长、flake 上限）。
- 与 ROADMAP 解冻门槛对齐，决定是否把 UI 自动化设为合并阻断项。

验收门槛：

- 连续 2 周无 P0 测试阻断误报。
- 文档口径与执行结果一致。

## 4. 风险与缓解

1. 工程化改造成本高：先保守落 D1/D2，再扩展用例。
2. macOS 权限与环境波动：测试环境标准化（权限预置 + 前台控制）。
3. 用例脆弱性：优先稳定标识符，不依赖视觉坐标。
4. 维护成本：限制首批用例数量，按风险优先级扩展。

## 5. 与 B 方案衔接

- 当前先执行 B（Debug-only 自动化）作为短期可交付。
- D 复用 B 产出的日志断言与链路分层经验，降低后续接入成本。
